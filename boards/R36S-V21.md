## Install

Follow the [main guide](../README.md) with the values above, then apply the fix below **before** the first boot.

## Known issue: rolling band and wrong colors

**Symptom:** the menu shows but the colors are off, and a blank horizontal band rolls down the screen whenever it redraws (for example, on every D-pad press).

**Cause:** this unit's stock DTB is a modified community build (its model reads "Game Console R35S/R36S fix by lxc"). Its `display-timings` section has a `native-mode` that points at a timing that doesn't exist.

- ArkOS ignores that and uses the first timing in the list: **29 MHz, about 59.94 Hz**. That's what the panel really needs.
- The Arch R generator doesn't fall back the same way. It builds a 60 Hz mode at 23.04 MHz with a much shorter vertical blank, and that causes the band.

**Fix:** the default mode in `mipi-panel.dtbo` has to be:

```
M clock=29000 horizontal=640,46,2,44 vertical=480,165,2,14 default=1
```

You can check what your file has with:

```bash
python3 tools/check_card.py /media/$USER/ARCHR --board v21
```

Look at the **Screen modes** section. If the `default=1` line shows `clock=23040` (or anything other than `clock=29000 ... vertical=480,165,...`), the file needs the fix.

**How to get a fixed file:**

1. **Best:** use the known-good `mipi-panel.dtbo` saved in [`dtbo/v21/`](../dtbo/). Copy it to `overlays/mipi-panel.dtbo`.
2. **To rebuild it yourself:** patch the stock DTB so `native-mode` points at the 29 MHz timing node, then run the generator on the patched DTB. On Linux with `device-tree-compiler` installed:
   ```bash
   dtc -I dtb -O dts -o v21.dts v21-stock.dtb 2>/dev/null
   grep -n -A3 'display-timings' v21.dts       # shows the native-mode line
   grep -n -B2 -A2 'clock-frequency = <0x1ba8140>' v21.dts   # 29000000 Hz timing node
   ```
   Set `native-mode = <...>;` to the `phandle` of that 29 MHz node, then:
   ```bash
   dtc -I dts -O dtb -o v21-fixed.dtb v21.dts
   ```
   Upload `v21-fixed.dtb` to the generator (R36S Original). Check the result with `check_card.py` as above.

> A regenerated overlay made from the **unpatched** DTB brings the band back. Always keep the known-good file.

## Known issue: buttons dead, OTG dead (card was used in a Soysauce)

**Symptom:** only Select (scrolls right) and Start (opens a menu) respond. The OTG port does nothing.

**Cause:** the card was set to the Soysauce board earlier, which pins `rk3326-gameconsole-soysauce.dtb` in `extlinux/extlinux.conf`. The Soysauce wires the D-pad, face buttons and USB differently.

**Fix:** see [Troubleshooting: buttons](../TROUBLESHOOTING.md#buttons). Switch the board back to `r36s`.
